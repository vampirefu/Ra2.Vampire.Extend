# 间谍自偷显式分支崩溃修复设计

## 崩溃证据与根因

AGWar 1.3.1 在提交“路径点 A → 残血友军兵营”的规划路径后发生 `0xC0000005`，异常 EIP 为未映射地址 `0x06451000`。

完整转储确认，异常现场的 `ESI=0x21186BA0` 是 `ENGINEER`，`EDI=0x211A0CE0` 是目标兵营；本次运行中的 SPY 是另一个对象 `0x21187298`。插件日志只有 Mission_Capture 目标注入，没有出现 `0x519D53` 的间谍分支日志。因此崩溃发生在工程师经过新增钩子的原版回退路径，早于间谍自偷分支。

`0x519D53` 覆盖的原指令包含相对条件跳转：

```asm
test al, al
jne 0x519FA2
```

当前非间谍路径使用 `return 0`，依赖 Syringe 恢复并执行这段原指令。崩溃表明该回退方式在当前 Ares、Phobos 和 Syringe 组合中不能安全处理此相对分支。

## 修复范围

只修改 `Ra2.Vampire.Extend` 的 `0x519D53` 钩子及其静态检查，不修改 Phobos、Ares、AGWar 配置或游戏本体。

保留钩子地址 `0x519D53` 和覆盖大小 `0x8`，但钩子不再返回 `0`。进入钩子后先保存原 `AL` 的结盟判断结果，再显式选择三个控制流出口：

```text
严格间谍 + 友军 Spyable 建筑 -> 0x519FF8
原 AL 非零                    -> 0x519FA2
原 AL 为零                    -> 0x519D5B
```

`0x519FA2` 完整保留工程师对友军建筑的维修/进入流程；`0x519D5B` 保留非友军目标的原版流程；只有严格间谍自偷场景进入现有 `0x519FF8` 渗透门，随后继续经过 Phobos 在 `0x51A002` 的事件钩子。

## 状态与兼容性约束

钩子不得修改 `Target`、`Destination`、路径点、规划令牌或任务，不得直接调用 `BuildingClass::InfiltratedBy`。不得在该钩子中使用 `return 0`，也不得让工程师执行间谍分支。

现有 `0x4D4B20` 目标保持钩子、`0x51EE4E` 动作钩子和 `0x519FF8` 最终渗透钩子保持不变。

## 验证

1. 先更新 PowerShell 静态检查，要求读取 `R->AL()`、显式包含 `0x519D5B`、`0x519FA2`、`0x519FF8` 三个出口，并禁止 `return 0`；修改实现前检查必须失败。
2. 实现显式三路分支后运行静态检查，要求通过。
3. 重新构建 Win32 Release 和 Debug，要求退出码为零；构建后再次运行静态检查。
4. 确认 AGWar 目录内没有运行中的进程，备份当前崩溃版 DLL 和日志，部署最新 Debug DLL并核对 SHA256。
5. 游戏内复测相同操作。验收标准：工程师经过 A 后正常进入兵营且不崩溃；间谍经过 A 后进入同一兵营并触发渗透。
